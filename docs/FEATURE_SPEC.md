## 2. 화면별 기능 상세

### 2.1 로그인 / 계정 연동 (F-01)

**설명**: Renaiss 계정과 연동된 X 또는 Web3 지갑으로 로그인한다.

| **항목** | **내용** |
| --- | --- |
| 입력 | X OAuth 인증 토큰 또는 Web3 지갑 서명 |
| 처리 | Renaiss 계정과의 연동 여부 확인 → 신규 유저면 계정 생성, 기존 유저면 세션 발급 |
| 출력 | 로그인 성공 시 대기 화면으로 이동 |
| 예외 | 인증 실패 시 에러 메시지 노출 및 재시도 유도 / Renaiss 미연동 계정인 경우 연동 안내 |

---

### 2.2 대기 화면 (F-02, F-03)

**기능: 방 생성**

| **항목** | **내용** |
| --- | --- |
| 설정 항목 | 최대 인원(최대 4인), 비밀번호 설정 여부, 공개/비공개 여부 |
| 처리 | 방 생성 시 고유 방 ID 발급, 방장 권한 부여 |
| 제약 | 인원 1~4명 범위 내 설정 |

**기능: 방 목록 조회 및 입장**

| **항목** | **내용** |
| --- | --- |
| 입력 | 공개방 목록 조회 요청 / 비밀번호 입력(비공개방) |
| 처리 | 정원 초과 또는 게임 진행 중인 방은 입장 불가 처리 |
| 출력 | 방 내부 화면(참가자 목록, 방장 표시) |
| 예외 | 비밀번호 불일치, 정원 초과, 방장 퇴장으로 인한 방 소멸 시 처리 정의 필요 |

**기능: 게임 시작**

| **항목** | **내용** |
| --- | --- |
| 권한 | 방장만 시작 가능 |
| 조건 | 별도의 개별 "준비" 절차 없이 방장의 시작 버튼 클릭만으로 전체 게임 시작 |

---

### 2.3 시작 화면 (F-04, F-05, F-06)

| **기능** | **설명** |
| --- | --- |
| 맵 선택 | 포켓몬 / 원피스 중 맵 선택시, 맵 디자인과 동일한 IP 카드 세트로 구성 |
| 맵 콘텐츠 선택 | 일반 / 롤링 / UP / 승리 / 상하이 중 택1 (방장 권한) |
| 난이도 선택 | 난이도별 카드 종류 수 및 타일 배치 밀도 차등 적용 (구체 수치는 밸런스 기획 별도 확정) |
| 소개 문구 | "실제 Renaiss 카드로 즐기는 입문 게임" 고정 텍스트 노출 |

---

### 2.4 게임 화면 – 기본 매칭 로직 (F-07)

| **항목** | **내용** |
| --- | --- |
| 입력 | 플레이어가 타일 2개를 순차 선택 |
| 처리 조건 | ① 두 타일의 카드 종류가 동일할 것, ② 두 지점을 연결하는 경로의 꺾임 횟수가 2회 이하일 것 |
| 처리 결과(성공) | 두 타일 제거, 연결선 이펙트 표시, 점수 증가, 도감 카운트 +1 |
| 처리 결과(실패) | 선택 해제, 페널티 없음(재시도 가능) |
| 막힘 처리 | 더 이상 매칭 가능한 짝이 없을 경우 자동 재배치 또는 힌트 표시 트리거 |
| 종료 조건 | 화면 내 모든 타일 제거 시 해당 플레이어 클리어 처리 |

---

### 2.5 맵 타입별 특수 규칙 (F-08)

| **맵** | **트리거 조건** | **동작** |
| --- | --- | --- |
| 일반 | 없음 | 기본 매칭 로직만 적용 |
| 롤링 | 3초 경과 | 카드 전체가 우측으로 이동, 연결 가능 각도 변경 |
| UP | 특정 층의 매칭 가능 카드 소진 | 최하단부터 카드 한 줄 추가 상승 |
| 승리 | "승리" 카드 짝 매칭 발생 | 해당 매칭을 처음 성공시킨 플레이어 즉시 1위 처리, 게임 즉시 종료 |
| 상하이 | 없음(맵 구조 자체가 겹층) | 상위 레이어 타일이 모두 제거된 하위 타일만 선택 가능하도록 처리 |

---

### 2.6 콤보 시스템 (F-09)

| **항목** | **내용** |
| --- | --- |
| 카운트 기준 | 연속 매칭 성공 횟수 |
| 5회 콤보, 15회 콤보 | 효과 발동: 플레이어가 화면 내 임의 카드 1종 지정 → 해당 카드의 짝 자동 제거 |
| 10회 콤보, 20회 콤보 | 효과 발동: 플레이어가 클릭한 카드와 동일 종류의 모든 카드를 화면에서 일괄 제거 |
| 초기화 조건 | 매칭 실패 또는 2초 이내 콤보 연결 실패 시 콤보 카운트 초기화 여부는 별도 확정 필요 |

---

### 2.7 아이템 시스템 (F-10)

| **아이템** | **수량** | **사용 조건** | **동작** | **비고** |
| --- | --- | --- | --- | --- |
| 서치 | 게임 당 3개 | 보유 수량 1개 이상 | 현재 매칭 가능한 짝 1쌍을 화면에 하이라이트(반짝임) 표시 |  |
| 카드 섞기 | 게임 당 3개 | 매칭 가능한 짝이 없는 상태(또는 자유 사용) | 전체 타일 재배치 | 위치만 변경, 카드 종류/개수 유지 |
| 가위 | 게임 당 1개 | 보유 수량 1개 이상 | 연결 경로 검증 없이 지정한 카드 1짝을 강제 제거 | 콤보 카운트 반영됨 |

---

### 2.8 순위 산정 및 게임 종료 (F-11)

| **항목** | **내용** |
| --- | --- |
| 1위 조건 | 모든 짝을 가장 먼저 제거한 플레이어 |
| 1위 확정 후 처리 | 10초의 클리어 유예 시간 부여 후 게임 종료 |
| 2위 이하 산정 | 유예 시간 종료 시점까지 남은 패 수 기준으로 점수 환산하여 순위 결정 |
| 동점 처리 | 별도 타이브레이커 규칙 확정 필요 |

---

### 2.9 도감 시스템 (F-12, F-13, F-14)

**기능: 카드 도감 적립 (F-12)**

| **항목** | **내용** |
| --- | --- |
| 적립 조건 | 동일 카드를 누적 10회 제거 |
| 처리 | 해당 카드를 유저 계정의 도감 데이터에 등록(카테고리: 포켓몬/원피스) |
| 데이터 | 라운드 단위 "오늘 만난 카드" 목록과 별개로, 계정 단위 누적 도감 데이터 유지 |

**기능: 도감 UI 및 마켓 연결 (F-13)**

| **항목** | **내용** |
| --- | --- |
| 카테고리 구분 | 포켓몬 / 원피스 탭 분리 |
| 카드 정보 표시 | 카드 이미지(우측 배치), 하단에 간단 스토리 또는 가격 정보 |
| 자세히 보기 | 클릭 시 Renaiss 마켓의 해당 카드 페이지로 외부 이동(또는 인앱 연결) |
| 정보 노출 정책 | 게임 진행 중에는 카드 제거 시 짧은 정보만 노출, 상세 학습 정보는 도감에서만 제공 |
| 데이터 정책 | 가격/등급 등 구체적 수치는 실제 Renaiss 데이터 기준, 미확보 시 예시 데이터임을 명시 |

**기능: 도감 완성 보상 (F-14)**

| **항목** | **내용** |
| --- | --- |
| 발동 조건 | 카테고리(포켓몬 또는 원피스) 도감 100% 달성 |
| 처리 | 해당 카테고리 전용 SBT 발급 및 유저 계정 지급 |

## 3. 화면 흐름도 (User Flow)

[로그인]

→ [대기 화면: 방 생성/입장]

→ [시작 화면: 맵/난이도 선택]

→ [게임 화면: 매칭 플레이]

→ [결과 요약 화면]

├─ "마켓 구경하기" → Renaiss 마켓 이동

├─ "보상 받기" → SBT 지급 처리

└─ 재플레이 → [대기 화면] 으로 복귀

## 4. 데이터 정의 (개략)

| **데이터 항목** | **설명** | **비고** |
| --- | --- | --- |
| 유저 계정 정보 | 로그인 식별자, 연동된 Renaiss 계정 정보 | F-01 |
| 방 정보 | 방 ID, 인원, 공개여부, 비밀번호, 방장 ID, 상태(대기/진행중) | F-02, F-03 |
| 라운드 결과 데이터 | 점수, 소요시간, 순위, 제거한 카드 목록 | F-11, F-15 |
| 도감 데이터(계정 단위) | 카드ID별 누적 제거 횟수, 등록 여부, 카테고리 | F-12, F-13 |
| 카드 마스터 데이터 | 카드ID, 카드명, IP(포켓몬/원피스), 등급별 가격/스토리 정보, 마켓 연결 URL | F-13, F-16 |
| 보상(SBT) 데이터 | 유저ID, 카테고리, 발급여부, 발급일시 | F-14 |

## 5. 별도 확정 필요 사항 (Open Issues)

1. 난이도별 카드 종류 수, 타일 배치 밀도 등 구체적 밸런스 수치
2. 롤링 맵의 이동 주기(초) 수치
3. 아이템(서치/섞기/망치) 획득 방식 및 1라운드 내 사용 가능 횟수
4. 콤보 카운트 초기화 조건(실패 시 / 시간 초과 시)
5. 순위 동점에 대한 특별한 추가 룰 없음. 그 즉시 게임 종료
6. 방장 퇴장, 비정상 종료(네트워크 끊김) 시 처리 정책
7. SBT 발행 체인 및 지갑 연동 기술 스펙
8. 카드 마스터 데이터(가격/등급) 갱신 주기 및 연동 방식(API 등)
9. 동시 접속자 규모 및 서버 인프라 요구사항
