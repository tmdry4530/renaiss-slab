# Renaiss Slab King — CTO 질의 목록 (해커톤 기준)

> 목적: 해커톤 CTO 질의응답용. **실서비스 운영이 아니라, 제한된 해커톤 시간 안에서의 판단**에 초점.
> 즉 "심사에 뭐가 유리한가 · 이벤트 동안 뭘 지원받나 · 뭘 진짜 연동하고 뭘 목업할까".
> 각 항목: **[Q]** 질문 · **[현황]** 지금 우리 구현 상태.
> 우선순위: 🔴 지금 결정 필요 · 🟠 중요 · 🟡 알면 좋음
>
> 구현 상태(2026-07 기준): 기능정의서 F-01~F-16 **전부 구현 완료** — 4인 실시간 멀티(서버 권위, Fastify+Socket.IO), 맵 모드 5종(일반/롤링/UP/승리/상하이), 콤보·아이템, 도감 적립, 결과 요약. **남은 목업은 SBT 발급과 로그인(게스트)뿐** → 질문도 여기에 집중.

## 1. 심사 기준 · 범위 (가장 먼저) 🔴

- **[Q1]** 이번 해커톤에서 **기술적으로 가장 높게 평가하는 축**은 무엇인가요 — (a) 온체인 실연동(SBT/가챠), (b) API 데이터 활용 깊이, (c) 완성도/UX, (d) 새로운 유스케이스?
  - [현황] 우리는 (b)+(c) 중심 — Index API + 공식 CLI 실데이터, 4인 실시간 멀티·맵 모드 5종·도감까지 완성. 온체인(SBT)만 목업.
- **[Q2]** 시간이 부족할 때 **SBT·가챠를 목업으로 두는 게 감점 요인**인가요, 아니면 "실데이터 활용 + 완성도"만으로도 충분히 경쟁력이 있나요?
- **[Q3]** "**Renaiss를 진짜 썼다**"고 인정되는 최소 기준이 있나요? (예: Index API 읽기만으로 OK인지, 온체인 트랜잭션이 1개는 있어야 하는지)

## 4. 데이터 연동 — 데모에서 보여줄 것 🟠

- **[Q10]** Index API 카드(`href`)와 마켓 매물(`tokenId`)을 잇는 **조인 키**가 있나요? "퍼즐에 나온 이 카드 → 실제 구매 매물"까지 데모에서 이으면 스토리가 완성됩니다.
  - [현황] 못 이어서, "자세히 보기"는 마켓 사이트 URL로만 연결.
- **[Q11]** 데모에서 **가격을 대표로 하나 표기**해야 하는데, `priceUsdCents`(Index) / `fmvPriceInUSD` / `askPriceInUSDT` 중 "이게 레퍼런스"라고 보여줄 값은 무엇인가요?
- **[Q12]** 베타라 커버리지가 부분적인데, 데모용으로 **확실히 데이터가 채워진 세트/카드** 추천 리스트가 있나요? (미커버는 "예시 데이터" 배지로 우회 중)
- **[Q21]** 🔴 SBT 발급 조건이 "카테고리 도감 100%"인데, **100%의 분모가 되는 공식 카드 목록**(카테고리별 canonical set)이 있나요? 지금은 우리가 긁어온 스냅샷 62종을 임의로 분모 삼고 있어서, 목록이 바뀌면 "도감 완성" 판정과 SBT 발급 조건이 함께 흔들립니다.
  - [현황] 도감 등록(카드당 누적 10회)·달성률·완성 판정·보상 지급까지 전부 구현됨. 분모만 비공식.

## 5. SBT · 가챠 — 실연동 가능성 🟠

- **[Q13]** 해커톤 시간 안에 **SBT 민팅을 실제로** 붙이려면, 우리가 컨트랙트를 직접 배포하나요 아니면 **Renaiss가 제공하는 민팅 API/컨트랙트**를 호출하나요? 가스는 누가 내나요?
  - [현황] 도감 완성 보상 SBT는 UI만 있고 발급은 목업.
- **[Q14]** 팩 개봉(가챠 pull)을 데모에 넣고 싶은데, 이벤트 기간에 **실행 가능한 형태**(테스트넷 tx/API)가 열려 있나요, 아니면 지금은 읽기 전용이라 목업이 현실적인가요?
- **[Q15]** 지갑 로그인(X OAuth / Web3)을 **하나의 Renaiss 계정에 매핑**하는 방식이 정해져 있나요? "Login with Renaiss" 같은 게 있으면 그걸 쓰고 싶습니다.
- **[Q22]** 지금은 게스트 playerId 기준으로 도감·SBT를 서버에 영속하는데, 나중에 실계정 로그인을 붙일 때 **게스트 진행 데이터를 계정으로 이관(merge)** 하는 걸 전제해도 되나요? 아니면 실계정 연동 시점에 도감을 리셋하는 게 정책상 맞나요? (SBT가 "달성 증명"이라면 이관 근거가 필요)
  - [현황] playerId 는 로컬 저장으로 재방문 유지, 도감은 서버 파일 영속. 계정 매핑은 없음.
- **[Q23]** SBT를 실민팅으로 바꿀 때, "도감 100% 달성"은 **우리 게임 서버만 아는 사실**입니다. Renaiss 민팅 쪽에서 달성 근거를 요구하나요(서명/검증), 아니면 우리 서버가 임의로 민팅 트리거해도 되나요? (부정 발급 방지 모델 확인)
  - [현황] 서버 권위 구조라 달성 판정 자체는 신뢰 가능, 발급만 목업.

- **[Q16]** 데모데이 현장 네트워크에서 **레이트리밋·API 장애**로 라이브 시연이 깨질 위험이 있는데, **사전 캐시/녹화 폴백**이 심사상 허용되나요?
