## 1. 개요

### 1.1 한 줄 소개

카드를 짝 지어 없애는 사천성 방식의 퍼즐을 즐기는 동안, 자연스럽게 Renaiss 카드의 가치와 구조를 배우고 실제 Renaiss 마켓으로 이어지는 입문용 캐주얼 게임.

### 1.2 배경 및 문제 정의

Renaiss는 PSA 등급을 받은 실물 수집 카드를 온라인에서 거래할 수 있는 플랫폼이다. 다만 신규 유저 입장에서는 진입 장벽이 존재한다.

- IP, TCG 카드 가치의 개념이 낯설다.
- 카드의 종류에 따라 가격이 크게 달라지는 이유가 직관적으로 이해되지 않는다.
- 텍스트 위주의 긴 설명은 완독률이 낮다.
- 가볍게 체험한 뒤 자연스럽게 마켓으로 넘어갈 입구가 부족하다.

### 1.3 솔루션

설명서 대신 **플레이를 통한 학습**을 제공한다. 사천성 형태의 매칭 퍼즐에 실제 Renaiss 등록 카드(포켓몬, 원피스)를 사용하고, 플레이 중 제거한 카드를 인게임 "도감"에 자동 적립하여 등급·가치·소유 개념을 자연스럽게 노출한 뒤 Renaiss 마켓으로 연결한다.

### 1.4 핵심 가치 흐름

게임 진입 → 퍼즐 몰입 → 도감을 통한 카드 가치 학습 → 마켓에서 실제 카드 확인 → 참여 보상(SBT) 수령 → 재방문

## 2. 목표 및 기대 효과

### 2.1 비즈니스 목표

1. **신규 유저 확보**: 캐주얼 게임으로 가볍게 유입된 유저를 마켓으로 전환
2. **교육 비용 절감**: PSA 10 기준 카드 시세 등 복잡한 개념을 게임 플레이로 대체 설명
3. **재방문 유도**: 참여 보상(SBT)을 통한 리텐션 확보
4. **성과 측정 가능성 확보**: 게임 플레이 유저 중 마켓 전환 비율을 정량 측정

### 2.2 차별점

1. 실제 Renaiss 카드를 게임 재료이자 학습 대상으로 활용
2. 도감을 통한 단계적 수집 지식 전달
3. 학습이 곧바로 마켓 구매 행동으로 연결되는 구조
4. 참여 보상(SBT)을 통한 재방문 유도

---

## 3. 대상 사용자 및 사용 시나리오

### 3.1 타깃 사용자

- Renaiss 신규 유입 유저 (수집 카드에 익숙하지 않은 사용자)
- 사천성류 캐주얼 퍼즐을 즐기는 일반 게임 유저
- 포켓몬/원피스 카드 IP에 관심 있는 기존 컬렉터

### 3.2 핵심 사용자 시나리오

1. X 또는 Web3 지갑 계정으로 로그인한다.
2. 방을 생성하거나 기존 방에 입장한다.
3. 1~3분 분량의 매칭 퍼즐 한 판을 플레이한다.
4. 결과 화면에서 오늘 만난 카드와 도감 달성률을 확인한다.
5. 관심 가는 카드를 "자세히 보기"로 눌러 Renaiss 마켓으로 이동한다.
6. 도감 완성 시 SBT 보상을 받고, 재방문 동기를 얻는다.

## 4. 핵심 기능 요구사항

### 4.1 게임플레이 기본 규칙

- 화면에 깔린 카드 타일 중 동일한 카드 두 장을 선으로 연결하여 제거하는 사천성 방식
- 연결선은 최대 2회까지 꺾일 수 있음(기존 사천성 규칙 준용)
- 화면의 모든 카드를 제거하면 한 판 종료
- 더 이상 맞출 카드가 없을 경우 자동 재배치 또는 힌트 제공
- 평균 플레이 시간: 1~3분

### 4.2 경기 방식

| **항목** | **내용** |
| --- | --- |
| 플레이 형태 | 개인전, 최대 4인 동시 참여 |
| 방 운영 | 방장이 맵 선택 및 게임 시작 가능 (개별 "준비" 절차 없음) |
| 승리 조건 | 모든 짝을 가장 먼저 제거한 플레이어가 1위 |
| 순위 산정 | 1위 외 플레이어는 남은 패 기준으로 점수화하여 순위 부여 |
| 종료 처리 | 1위 확정 후 10초의 클리어 유예 시간 부여 |

### 4.3 맵 콘텐츠 종류

| **맵 콘텐츠 유형** | **규칙 설명** |
| --- | --- |
| 일반 | 기본 매칭 규칙 |
| 롤링 | 3초마다 카드가 우측으로 이동하며 연결 각도가 변화 |
| UP | 최하단부터 카드가 한 줄씩 상승, 해당 층의 제거 대상이 없어지면 한 층 추가 상승 |
| 승리 | "승리" 카드 짝을 가장 먼저 연결한 플레이어가 즉시 승리 |
| 상하이 | 카드가 겹층으로 구성된 입체형 사천성 |

### 4.4 콤보 시스템

- 콤보 지속시간 2초
- 5회차마다 콤보 발생
- 5회차 콤보: 원하는 카드 1종의 짝을 임의 제거 가능
- 10회차 콤보: 클릭한 카드와 동일한 카드 전체 제거
- 15회차 콤보: 원하는 카드 1종의 짝을 임의 제거 가능
- 20회차 콤보: 클릭한 카드와 동일한 카드 전체 제거

### 4.5 아이템 시스템

| **아이템** | **효과** |
| --- | --- |
| 서치(Search) | 현재 연결 가능한 짝 하나를 화면에 강조 표시 |
| 카드 섞기(Shuffle) | 연결 가능한 짝이 없을 때 전체 카드를 재배치 |
| 가위(Scissor) | 연결 경로와 무관하게 지정한 카드 한 짝을 강제 파괴 |

### 4.6 도감 시스템 (핵심 기능)

- 동일 카드를 누적 10회 제거 시 인게임 도감에 등록
- 라운드 종료 후 "오늘 만난 카드" 목록, 도감 달성률, 만난 카드 중 최고가 카드를 요약 제공
- 도감이 전달하는 정보는 캐릭터 서사가 아닌 **실용적 수집 지식**:
    1. 소유 개념: 온라인 구매 카드의 소유권 의미, 실물 카드 수령 가능 여부
    2. 컬렉션 개념: 세트/시리즈의 의미

**도감 UI 구성**

- 카테고리 구분: 포켓몬 / 원피스
- 카드를 우측에 노출, 하단에 간단한 스토리 또는 가격 정보 표기(PSA 10 등급 기준)
- "자세히 보기" 클릭 시 Renaiss 마켓 페이지로 연결(PSA 10 등급 기준)
- 도감 완성 시 카테고리별(포켓몬/원피스) 특별 SBT 보상 지급
- 설계 원칙: 매 제거 시점마다 긴 설명창을 띄우지 않고, 정보 열람은 도감에서 선택적으로 이루어지도록 분리 (퍼즐의 속도감 유지)

## 5. 화면 요구사항 (Screens)

### 5.1 대기 화면

- 방 만들기: 인원 수, 비밀번호 설정, 공개 여부 설정
- 생성된 방에는 실제 유저가 참여하여 함께 플레이 가능

### 5.2 시작 화면

- 게임 제목, 맵 선택, 난이도 선택, 시작 버튼
- "실제 Renaiss 카드로 즐기는 입문 게임" 소개 문구 노출

### 5.3 게임 화면

- 카드 타일이 배치된 맵
- 점수, 남은 카드 수, 타이머
- 서치 / 섞기 / 가위 버튼
- 카드 매칭 시 연결선 이펙트와 함께 카드 제거 연출

### 5.4 마무리 요약 화면

- 클리어 여부, 점수, 소요 시간, 획득 경험치
- 오늘 만난 카드 목록, 최고가 카드
- 마켓 구경 버튼, 보상 받기 버튼

### 5.5 전체 플레이 루프

게임 시작 → 게임 종료 → 스코어 공개(리더보드) → 도감 달성률 확인 → 게임 시작(반복)

## 6. 맵 비주얼 컨셉

- 매 라운드 고정된 사각형이 아닌 다양한 형태의 맵 모양 적용 (시각적 재미 및 재플레이 유도)
- 포켓몬 / 원피스 중 맵 선택시, 맵 디자인과 동일한 IP 카드 세트로 타일 구성
- 디자인 모티브 예시:
1. 포켓몬 관련 요소 (피카츄, 리자몽, 꼬북이, 이상해씨, 몬스터볼)
2. 원피스 관련 요소 (루피, 나미, 쵸파, 밀짚모자, 해적 깃발, 악마의 열매)
- 위 요소는 단순화된 그래픽 형태로 구성

## 8. 비기능 요구사항

### 8.1 정책 / 컴플라이언스

- 본 게임은 수익을 창출하지 않으며 과금 요소를 포함하지 않는다.
- 영리 목적이 아닌, 유명 카드 IP(캐릭터 그림, 이름, 로고)를 활용한 팬게임으로 운영한다.
- 실제 데이터가 아직 확보되지 않은 화면에서는 예시 데이터임을 명확히 표기한다.
- 시세 및 등급 등 구체적 수치는 반드시 실제 자료를 기준으로 하며 임의 생성을 금지한다.

### 8.2 성과 측정 (제안)

PRD 작성 시점에서 구체적 KPI 수치는 미정이나, 최소 다음 지표의 트래킹 설계가 필요하다.

- 게임 플레이 유저 수 / 재방문율
- 도감 열람 → 마켓 "자세히 보기" 클릭 전환율
- 마켓 페이지 이동 → 실제 구매 전환율
- 도감 완성 및 SBT 수령 비율

## 9. 범위 외 사항 (Out of Scope) / 확정 필요 사항

- 결제·과금 시스템: 명시적으로 제외 (정책상 수익화 없음)
- 실제 카드 시세·등급 데이터 연동 방식(API/주기적 갱신 등)은 별도 정의 필요
- SBT 발행/지급 체계의 기술적 구현 방식(체인, 지갑 연동 등)은 별도 기술 문서 필요
- 동시 접속 인원 규모, 서버 아키텍처 등 인프라 요구사항은 본 PRD 범위 외

## 10. 용어 정리

| **용어** | **설명** |
| --- | --- |
| PSA 등급 | 카드 감정 기관 PSA가 부여하는 카드 상태 등급 |
| 도감 | 게임 내 누적 수집 기록 UI, 카드별 학습 정보 제공 |
| SBT | Soul Bound Token, 양도 불가능한 참여/달성 보상 토큰 |
| 슬랩(Slab) | 등급 감정 후 보호 케이스에 봉인된 카드를 지칭하는 용어 |
